Accessibility Features
Screen Reader Support: All spell icons have full aria-labels describing spell type, mana cost, cooldown status, and silence state. Tooltips use aria-live="polite" for damage prediction updates. Tile grid uses role="button" with tabindex for keyboard navigation.
Keyboard Navigation: Complete tab order through spell rail, arrow keys to cycle within rail or through enemy tiles during targeting. ESC always cancels targeting. No pointer-device required.
Touch Parity: Tap to cast (< 100ms, < 3px drift), tap-and-hold 400ms to show tooltip. Tooltip remains until user taps outside. Gesture-free alternative: 44×44px buttons ensure all interactive elements are reachable by touch.
Reduced Motion: Users with `prefers-reduced-motion: reduce` OS setting see static UI states instead of pulses and floats. Ready pulse becomes a static glow. Damage numbers appear in a log line instead of floating.
Animation Timing (Phase 06)

All animations are optimized for snappy feedback without motion sickness triggers.

Animation Duration Easing
Tooltip fade-in 120ms ease-out
Spell icon ready-pulse (idle loop) 1.4s ease-in-out (infinite)
Card rim glow pulse (active state) 1.4s ease-in-out (infinite)
Tile hover glow (targeting) 150ms ease-out
Damage number float-up 600ms cubic-bezier(0.1, 0.8, 0.8, 1)

Total motion budget per turn: ~3–5 seconds cumulative. Respects `prefers-reduced-motion` OS setting.

Implementation Notes for Phase 10 & 11

Touch Interaction Thresholds

  • Tap: < 100ms duration, < 3px drift — fires action immediately, no tooltip
  • Hold: 400ms+ on touch device — shows tooltip, allows inspection before release
  • Hover (pointer): 200ms debounce on pointer enter, instant dismiss on leave

Tooltip Positioning Rules

  • Desktop: Floats right of HUD card row, 8px minimum gap to viewport edge
  • Mobile: Slides up from bottom as partial sheet, ~160px tall, does not cover spell rail
  • Targeting: Shows predicted damage against hovered enemy, live-updated per hover

Damage Prediction Formula

Uses `computeDamage(caster, target, spell, weapon)` from `src/game/formulas.js`. Must account for:

  • Caster's current stats (STR, INT, DEX)
  • Target's armor and resistances (factored in real-time)
  • Crit chance and RNG variance (show range, not single number)
  • Status vulnerabilities (e.g., +25% fire weakness)
Focus Management: When AWAITING-INPUT is set, focus automatically moves to the first spell icon in the active hero's rail. During targeting, focus moves to the first enemy tile. ESC returns focus to the spell that started targeting.
